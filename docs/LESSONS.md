## 2. 전략에서 배운 것

1. **엣지(우위)를 증명하기 전에 실돈으로 운영했다.** 백테스트나 페이퍼 트레이딩 없이 실계좌에서 규칙을 "학습"했다. 4개월에 39건으로는 어떤 규칙의 효과도 통계적으로 구분할 수 없다. 규칙을 바꿀 때마다 표본이 다시 0이 됐다.
2. **진입 품질이 핵심 병목이었다.** 30일 모멘텀 상위를 스크리닝해서 RSI<65로 거르는 구조는, 이미 오른 종목을 늦게 사는 쪽으로 기울었다. 진입 직후 실패율이 43%였다.
3. **LLM의 '확신도'는 엣지의 원천이 아니었다.** 지표만으로 매긴 '상' 진입은 1승 7패였다. 촉매(회사 사건)를 요구한 뒤에도 5건 평균 −1.48%였다.
4. **재량 청산이 손익비를 망가뜨렸다.** 기계적 TP/SL보다 LLM 판단이 먼저 개입했고, 이익은 짧게, 손실은 상대적으로 길게 가져갔다.
5. **계좌가 작아 구조적 비용이 컸다.** 총자산이 약 $300이라 20% 배분이면 포지션 하나가 $60이다. 소수점·금액 주문 제약이 생기고, 환율 변동 한 번이 몇 주치 매매 손익보다 컸다.
6. **벤치마크를 처음부터 재지 않았다.** QQQ 대비 측정은 11월에야 시작했다. 같은 기간 "아무것도 안 하고 QQQ를 들고 있기"와 비교했어야 했다.
7. **중단 기준을 미리 정하지 않았다.** "언제 수익 내냐"는 질문에 답할 기준이 없어서, 성과 점검 날짜(11/29)를 뒤늦게 약속했다.

## 5. 재설계 방향 (제안)

시스템 설계에 대한 제안이다. 투자 판단(다시 할지, 얼마를 넣을지)은 사용자 몫이다.

1. **검증 먼저, 실돈은 나중.**
   - 과거 캔들로 규칙을 재현하는 백테스트 하네스를 먼저 만든다. 규칙이 코드면 백테스트가 가능하다(§5-2).
   - 그다음 `TOSS_DRY_RUN=true` 페이퍼 운영으로 표본(예: 30~50건)을 쌓는다.
   - 실계좌 전환 기준을 **미리 숫자로** 정한다. 예: 손익비 > 1.2 이고 같은 기간 QQQ 대비 플러스.
2. **규칙은 코드로, LLM은 좁은 역할로.**
   - RULES_FINAL.md의 C층 중 '가능' 표시 규칙(RSI·이격·배분·섹터·재진입·만료·비중)은 전부 결정적 코드로 옮긴다.
   - LLM은 "이 뉴스가 종목 직결 회사 사건인가, 사건일은 언제인가" 같은 **구조화된 분류**만 한다. 출력은 JSON 필드, 판단은 코드.
   - Manager의 SELL 권한을 없앤다. 청산은 감시기만 한다.
3. **자기수정 루프는 제안만, 승인은 사람이.** 주간회고는 "이런 변경을 제안한다 + 근거 + 백테스트 결과"를 쓰고, 규칙 변경은 사용자가 승인해야 반영되게 한다.
4. **첫날부터 벤치마크와 중단 기준.** 매일 QQQ 대비를 기록하고, 사전에 정한 중단 기준(예: 3개월 QQQ 대비 −5%p)에 닿으면 자동으로 dry-run으로 내려가게 한다.
5. **계좌 규모와 비용을 설계 입력으로.** 소액이면 환율·소수점 제약·운영 비용이 성과를 지배한다. "QQQ 적립"이라는 가장 단순한 대안을 항상 비교 대상으로 둔다.
6. **집행 대기 상태를 DB에 저장.** 재시작으로 그날 매매가 사라지는 약점을 구조적으로 없앤다.

검토해 볼 대안 구조 (우열 판단은 백테스트 뒤에):
- (a) 규칙 기반 모멘텀/평균회귀 — 전부 코드, LLM 없음. 백테스트가 가장 쉽다.
- (b) (a) + LLM 리스크 필터 — 코드가 후보를 내고, LLM은 "피해야 할 사건(소송·회계 문제 등)"만 거부권을 가진다.
- (c) 지수 추종 + 규칙 리밸런싱 — 비교 기준선 겸 대안.
